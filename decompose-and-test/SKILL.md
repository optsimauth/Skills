# 分解 + 测试统一流程（强制，禁止跳步）

## 铁律

任何代码生成/重构任务，必须按以下 5 步**顺序**执行，禁止跳步、禁止合并、禁止简化（除非命中下方"简化例外"）：

1. **按 `layered-function-decomposition` 规则写代码**：编排函数只调用，叶子函数 3～15 行单一语义，Step-down 排列。产出 `src/xxx.py`。
2. **列出待测清单**：列出所有叶子函数（函数名、参数、职责）。编排函数若含分支逻辑，也必须补一条行为测试。
3. **按 `pytest-io-testing` 规则为每个叶子函数写输入输出对测试**，格式与取舍标准完全遵照该 skill，不得自创格式。
4. **编排函数写集成测试**（若含业务分支判断则必须写，不含则跳过）：可 mock/spy 内部叶子函数，只验证调用顺序与参数传递，禁止重复断言叶子函数内部计算逻辑。
5. **执行 `pytest -v` 并汇报**：
   - 全 PASS：必须明确告知"N 个叶子函数、M 条测试全部通过"，并附函数调用关系目录。
   - 有 FAILED：必须先判定测试数据错误还是代码逻辑错误，明确定位到具体叶子函数，禁止甩报错原文了事。

## 简化例外（仅限以下情形，其余一律走完整5步）

- 一次性脚本 ≤10 行、无分支/校验/副作用：可跳过分层分解，但核心函数仍必须配 2～3 组输入输出测试。
- 用户明确要求"先不写测试，只看逻辑"：先完成第1～2步并展示拆分结果，待确认后再做第3～5步。
- 纯配置/纯数据文件：本流程不适用。

## 自查清单（交付前逐条核对，任何一项不满足禁止交付）

- [ ] 编排函数与叶子函数职责完全分离，无混层
- [ ] 每个叶子函数都有对应测试用例
- [ ] 每个 assert/raise 断言都能让用户不看代码即知错在哪
- [ ] 已实际执行 `pytest -v` 并展示结果（尤其 FAILED 详情）
